# typ0s autoresearch: rules for experiment agents

You are improving typ0s, a macOS typo fixer for fast freewriting. You work in `~/typ0s-autoresearch` on branch `autoresearch/overnight`. Each experiment: change the engine, measure it, keep it only if it's better.

## The score

```bash
cd ~/typ0s-autoresearch && tools/autoresearch/experiment.sh
```

It takes about 4 minutes. **Run it with a Bash timeout of 600000 ms** (the default 2 minutes is too short). It rebuilds, retrains both learned models (`RankModel.swift`, `FixGate.swift`) on the fit split, scores on the validation split, then runs safety checks. It prints:

- `SCORE <n>`: higher is better. It equals fixed typos − 2 × wrong words − 4 × damaged clean sentences (Bold mode).
- `GUARDS PASS` or `GUARDS FAIL: <why>`. A change is only kept if the guards pass.

Baseline at the start: **SCORE 1352**, guards pass.

## One experiment

1. Read `tools/autoresearch/results.tsv` and `git log --oneline` so you don't repeat what was tried.
2. Pick **one** idea, and keep it small and general.
3. Edit the code.
4. Run the experiment script.
5. **Keep** it only if SCORE beats the best kept score so far **and** GUARDS PASS:
   `git add -A && git commit -m "exp: <idea> (SCORE <n>)"`.
   Otherwise discard it: `git reset --hard HEAD`.
6. Append one line to `tools/autoresearch/results.tsv` (it's untracked, so it survives resets):
   `<SCORE>\t<kept|discarded>\t<guards>\t<one-line idea>`

## What you may change

- `FastTypoEngine.swift`: candidate search, ranking features, gate features, `TypoTuning` values, split/join logic, grammar rules.
- `WordModel.swift`: how the word lists are used (not the list files themselves).
- `tools/train/main.swift`: **learning code only** (features, optimisation, regularisation, cut-off selection). Keep feature lists in sync with the engine.
- `RankModel.swift` / `FixGate.swift` are regenerated by the script. Don't hand-edit them.

## What you must not do

- Don't change how the score is computed: `Score`, `score(...)` and the `eval` mode in `tools/train/main.swift`, or `tools/autoresearch/*`.
- Don't edit or read for ideas `data/*_test.tsv`, `data/*_val.tsv`, `tests/real_typos.tsv` or `tests/clean_text.txt`. They're the exam. You may look at `data/*_fit.tsv`.
- Don't hard-code specific words or sentences from the data, and don't add entries to `instantFixes`, `bareContractions` or the user dictionary. That's memorising, not improving.
- Don't edit `data/`, `tests/`, `Dictionary/`, `Typ0sApp.swift`, `Typ0sUI.swift` or `build.sh`.
- Don't push, don't touch `~/typ0s` (the user's main copy), don't install the app, and don't run `git clean`.
- Average speed must stay under 60 ms per sentence (the guards check this).

## Where the errors are (from analysis on the fit data)

- Space-bar slips (a word split or two words joined) are the biggest error group.
- Next: picking the wrong real word (e.g. `tyh` → "they" instead of "the").
- Then: typos needing 3+ edits, and gate cut-offs that leave fixable words alone.
- About 6% of typos turn into another real word ("form" for "from"). The real-word check exists but is off (`realWordMargin = .infinity`).

## Idea starters (not orders)

- Ranker features: same-hand / same-row slip, bigram fit on both sides combined, word-length ratio, how many slips were neighbour-key vs dropped.
- Gate features: margin between the best two learned-ranker scores, typed word's own frequency of appearing in the list as a misspelling-like token.
- Candidate generation: better skeletons, pruning ultra-rare dictionary words as candidates (very low frequency words often win wrongly).
- Space slips: smarter join/split choices using pair frequencies on both sides.
- Learning: more ranker iterations, L2 strength, class balance in the gate, pairwise features.
